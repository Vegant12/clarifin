<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `pdfBytes` (raw PDF) → Langfuse trace payload | Per AI-SPEC §3 pitfall 5 — passing raw PDF bytes as generation `input` would exceed Langfuse's 1MB event byte limit and pollute trace UI. Hard boundary: only prompt strings + metadata cross. |
| Gemini error → user-facing response | Exceptions thrown by Gemini must propagate to the caller unchanged; Langfuse instrumentation must be observer-only, not transformer. |
| Trace metadata → Langfuse Cloud | `doc_id` is a UUID with no PII per existing schema. `commit` is a public git SHA. Prompt text contains no PII because PDFs are anonymous. Acceptable to send. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-05 | Information Disclosure | Raw `pdfBytes` accidentally logged as `generation.input` blows trace size + leaks document content into Langfuse Cloud beyond what's necessary | mitigate | Action explicitly enumerates `input: { prompt, docId, isIndonesian, totalPages }` — NO `pdfBytes` field. Acceptance criterion includes manual grep verification. Per AI-SPEC §3 pitfall 5. |
| T-11-06 | Repudiation | Error in Gemini call bypasses `generation.end()` leaving orphan observations; quality regression cannot be attributed because trace looks incomplete | mitigate | `try/catch/finally` ensures `generation.end({ level: "ERROR" })` fires before re-throw; `flushAsync()` fires regardless. Test case 3 (Task 1) asserts both. Per AI-SPEC §3 pitfall 4. |
| T-11-07 | Denial of Service | Langfuse `flushAsync()` failure (network hiccup) crashes the analyze-batch pipeline | accept | `flushAsync()` is awaited inside `finally`; if it throws, the original Gemini error (if any) is masked. Acceptable because flush failures are rare and the alternative (silent .catch) loses the entire trace. If flush itself throws, the catch in the calling code (`analyze-document-batch.ts`) records failure status and the cron retries the document — no data loss. |
| T-11-08 | Tampering | A future commit moves `flushAsync()` outside `finally` (e.g., into success path only); errors silently lose traces | mitigate | Acceptance criterion grep counts exact occurrence (`-c "await langfuse.flushAsync()"` = 1) AND placement is documented in JSDoc + AI-SPEC §3 pitfall 1. Test asserts flushAsync called on both success and failure paths. |
| T-11-09 | Information Disclosure | Prompt logged to Langfuse includes injected document text (prompt injection) which could contain malicious payload visible in trace UI | accept | This is intentional and beneficial — trace UI is the diagnostic surface for prompt injection (per AI-SPEC Critical Failure Mode #4 / Section 1b "Prompt injection via document content"). Langfuse access is gated by project credentials (only the developer). |
