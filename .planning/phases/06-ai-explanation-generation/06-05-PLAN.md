<objective>
Phase 6 SUCCESS CRITERION #5 from ROADMAP.md is:

> **[EVAL GATE — blocking]** The eval harness scores ≥90% numeric accuracy AND ≥90%
> citation accuracy on the 9-document eval set before this phase is signed off.

This plan is the BLOCKING gate. It does not write production code — it runs the existing
`pnpm eval` harness (built in Phase 5, already merged) plus a manual end-to-end smoke test
that uploads a single fixture PDF through the full pipeline (parse → embed → analyze) and
confirms the resulting `document_analysis.explanation` row is well-formed.

Two checkpoints, both blocking:
1. **Eval gate** — `pnpm eval` exits 0 against the 9 corpus PDFs (Phase 5 corpus from
   Plans 05-01 and 05-02 must be `ready` status in `eval/manifest.json`).
2. **Live smoke** — upload one fixture PDF via the running app, watch the pipeline
   complete, inspect the persisted `document_analysis.explanation` JSON, confirm the
   5 sections + `[p.N]` citations + no untranslated PSAK terms.

If either gate fails, the executor must surface the failure to the user — DO NOT attempt
to widen tolerances or skip documents. Per CLAUDE.md project constraints: "Citations
non-negotiable" and "AI quality is the single biggest technical risk and must be validated
with a small eval set early."

Purpose: Lock the success criterion before Phase 7 (Citation UI) starts consuming the
cached explanation. Phase 7 must not be built on an unvalidated AI output layer.
</objective>
