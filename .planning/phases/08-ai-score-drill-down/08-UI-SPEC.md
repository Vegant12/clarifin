## Visual Hierarchy

**Primary focal point in Phase 8:** The 48px emerald-600 score number is the visual anchor of the score card. It is larger than any other text element in the document reader. The eye lands on it first, then reads the disclaimer below it, then scans the 4 dimension rows.

**Reading flow:** Score number (display/emerald) → disclaimer (sm/muted) → 4 dimension rows (label + chip + reasoning) → [click to expand] → snippet pull-quotes + citation links.

**Score card placement:** Prepended above all 5 explanation sections in `ExplanationPanel`. The score card renders as a dedicated `<section>` before the `SECTION_ORDER` map, separated from the first explanation section by 24px (`gap-6` in the existing `flex flex-col gap-12` article — or wrapped in its own gap).

## Score Card Anatomy

### Score Header Block

```
┌─────────────────────────────────────────────┐
│  7                                          │
│  (48px, weight 600, emerald-600)            │
│                                             │
│  AI Assessment · not financial advice       │
│  (14px, weight 400, muted-foreground)       │
└─────────────────────────────────────────────┘
```

- Score number: `text-5xl font-semibold text-primary` (maps to 48px / 600 / emerald-600)
- Disclaimer: `text-sm text-muted-foreground` directly below the number, same block, no separator

### Dimension Rows (Accordion Triggers)

4 rows stacked vertically inside a shadcn `Accordion type="single" collapsible`. Each row:

```
┌───────────────────────────────────────────────────────────┐
│  Profitability          [8/10]     The company's net...   │
│  (14px/600/foreground)  (chip)     (14px/400/foreground)  │
└───────────────────────────────────────────────────────────┘
```

Layout within each `AccordionTrigger`:
- Flex row, `justify-between`, `items-start`
- **Left:** dimension name — `text-sm font-semibold text-foreground`
- **Center-left:** one-sentence reasoning — `text-sm text-foreground leading-snug` (truncated to 1 line on mobile with `line-clamp-2` on desktop allowed)
- **Right:** sub-score chip — `[N/10]` badge, same visual pattern as citation badge from Phase 7: `rounded-full bg-primary px-2 py-0.5 text-primary-foreground text-xs font-semibold`

The chevron rotate animation from the default shadcn Accordion is retained (rotates 180° when open).

### Accordion Content — Snippet Pull-Quotes

When a dimension row is expanded, 2–3 snippet blocks animate open below it:

```
┌──────────────────────────────────────────────────────┐
│  │ "Laba bersih setelah pajak mencapai Rp 48 triliun │
│  │  pada tahun 2023."               [p.47]           │
└──────────────────────────────────────────────────────┘
```

Each snippet block:
- Outer: `border-l-2 border-muted pl-3 py-1 my-1`
- Quote text: `text-sm italic text-foreground` — verbatim, not paraphrased
- Citation: `CitationInline` from Phase 7 appended inline after the quoted text, same `[p.N]` emerald badge behavior (click → PDF scroll, hover → popover)
- Snippet block background: `bg-muted/40` (zinc-100 at 40% opacity) — slightly inset feel, not a full card

Multiple snippets within one dimension: stacked vertically with `gap-2` inside `AccordionContent`.

## Score Card States

### State 1: Loading (analysis in progress)

Document status is not yet `ready`. Score card slot shows an animated skeleton in place of the score header and dimension rows.

Skeleton layout (mirrors `PdfLoadingSkeleton` pattern):
- Score number placeholder: `h-12 w-16 animate-pulse rounded-md bg-muted` (approx 48px tall, 64px wide)
- Disclaimer placeholder: `h-4 w-40 animate-pulse rounded bg-muted mt-2`
- 4 dimension row placeholders: `h-10 w-full animate-pulse rounded-md bg-muted`
- All skeletons share `animate-pulse` and `bg-muted` (zinc-100 fill)
- `role="status"` `aria-label="Loading AI assessment…"` `aria-busy="true"` on the container

### State 2: Score Available (nominal)

Score card renders as described in Score Card Anatomy above.

### State 3: Score Unavailable (soft-fail null)

When document is `ready` but `score` is null (per CONTEXT.md D-02, D-07):

```
┌────────────────────────────────────────────────┐
│  AI Assessment unavailable                     │
│  (16px, weight 600, muted-foreground)          │
│                                                │
│  The AI assessment could not be generated      │
│  for this document.                            │
│  (14px, weight 400, muted-foreground)          │
└────────────────────────────────────────────────┘
```

- Container: `rounded-lg border border-border bg-muted/30 px-4 py-4`
- Heading: `text-base font-semibold text-muted-foreground`
- Body: `text-sm text-muted-foreground mt-1`
- No score number rendered, no dimension rows rendered
- Explanation sections still render below (unaffected)

## Responsive Layout

The score card lives inside `ExplanationPanel`, which is already responsive via `DocumentReaderLayout`:

| Breakpoint | Behavior |
|------------|----------|
| ≥769px (desktop) | Score card renders at full width in the left explanation panel of the split pane |
| ≤768px (mobile) | Score card renders in the "Explanation" tab of `MobileTabView` — full viewport width, stacked above explanation sections |

No layout restructuring to `DocumentReaderLayout` or `DesktopSplitPane` (per CONTEXT.md D-06).

On mobile (375px+), the accordion is fully functional — tap to expand, tap again to collapse. The sub-score chip and reasoning text wrap naturally. Dimension name: 14px. Reasoning sentence: 14px with `line-clamp-2` on mobile to prevent excessive height before expansion.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Disclaimer label | "AI Assessment · not financial advice" |
| Score unavailable heading | "AI Assessment unavailable" |
| Score unavailable body | "The AI assessment could not be generated for this document." |

| Sub-score chip format | "[N/10]" (e.g., "[8/10]") — brackets included, always |
| Snippet citation format | "[p.N]" (Phase 7 CitationInline — unchanged) |

No primary CTA in Phase 8 — the score card is informational, not action-driving.
No destructive actions in Phase 8 — no confirmation copy needed.
No empty state beyond "unavailable" — if score is null, the unavailable state covers it.

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Score number semantics | Wrapped in `<p>` or `<span>` with `aria-label="Overall AI assessment score: N out of 10"` |
| Disclaimer proximity | Disclaimer immediately follows score number in DOM order — no skip elements between them |
| Accordion keyboard nav | shadcn Accordion (Radix `@radix-ui/react-accordion`) — full keyboard nav by default: Tab focuses trigger, Enter/Space toggles, Arrow keys navigate between triggers |
| Accordion ARIA | Radix handles `aria-expanded`, `aria-controls`, `role="button"` on triggers automatically |
| Snippet citation access | `CitationInline` Phase 7 accessibility unchanged — `tabIndex={0}`, Enter/Space to navigate, `aria-label="View source for page N"` |
| Unavailable state | Rendered in a `<section>` with plain text — no interactivity, no additional ARIA needed |
| Loading skeleton | `role="status"` `aria-label="Loading AI assessment…"` `aria-busy="true"` on skeleton container |
| Focus order | Score card appears first in tab order within `ExplanationPanel`; dimensions are traversable before explanation sections |
