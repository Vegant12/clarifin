MOBILE BREAKPOINT RULE: The project uses ONE breakpoint: `md` (768px). Do NOT introduce sm: on layout containers — only on typography (matching page.tsx line 38 precedent: `sm:text-4xl`).

From src/app/page.tsx line 32 (safe 375px container pattern — already correct):
```tsx
<main className="mx-auto flex min-h-screen max-w-3xl flex-col gap-16 px-6 py-16">
```
max-w-3xl (768px) + px-6 (24px each side) → 327px content width at 375px. Safe.

From src/app/page.tsx line 49 (step grid — may need audit):
```tsx
<section className="grid gap-4 sm:grid-cols-3">
```
Without sm:, this is 1-column. With sm: it switches to 3-column at 640px. At 375px it's 1-column — safe. No change needed.

From src/components/upload/pipeline-stepper.tsx line 65 (stepper layout):
```tsx
<ol className="flex w-full flex-wrap items-start justify-between gap-4 gap-y-6 text-sm md:flex-nowrap">
```
At 375px (mobile), this is flex-wrap — each step wraps onto its own line. With min-w-[5.5rem] on each <li>, and 3 steps, this can wrap to 2 or 3 rows. That's acceptable but the individual <li> at line 75 has `min-w-[5.5rem]` — ensure the text inside steps doesn't overflow the li width.

From src/components/upload/pipeline-stepper.tsx line 75 (step item):
```tsx
<li className={cn("flex min-w-[5.5rem] flex-col items-center gap-2 md:flex-1")}>
```
Step labels ("Parsing", "Embedding", "Analyzing") at text-sm are short enough. The status text below each icon could overflow if very long — check the failed state renders safely.

From src/components/doc/score-card.tsx lines 47-48 (accordion trigger row):
```tsx
<div className="flex w-full items-center gap-2 pr-2">
  <span className="text-sm font-semibold text-foreground flex-1">{dim.name}</span>
  <span className="rounded-full bg-primary px-2 py-1 text-primary-foreground text-xs font-semibold">
    {`[${dim.score}/10]`}
  </span>

```
The `flex-1` on the name span causes it to take available width, pushing the score badge right. At 375px, this is safe — dim.name values ("Profitability", "Balance Sheet", "Growth Trend", "Valuation Context") max out at ~18 chars at text-sm. No overflow risk. However, the snippet blocks inside AccordionContent may need `min-w-0` to prevent long quoted text from overflowing.
