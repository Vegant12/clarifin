## 1. System Classification

**System Type:** RAG-grounded Conversational

**Description:**
A document-grounded streaming chat assistant for Clarifin. Indonesian retail investors who upload IDX-listed company financial documents can ask follow-up questions about the document in plain English and receive streamed answers grounded in retrieved page chunks, each answer carrying page-level citations back to the source PDF. Sessions persist for 7 days via anonymous UUID. The system opens with 3–5 suggested questions specific to the uploaded document and deflects any investment-recommendation requests.

**Critical Failure Modes:**
1. Answer fabricates facts not present in the document (hallucination without grounding in retrieved chunks)
2. Citation page numbers are wrong — user clicks through to a page that doesn't contain the claimed information
3. The buy/sell investment-advice guardrail fails and the system produces a recommendation ("buy this stock" / "the stock is a good investment")
4. Streamed partial answer is incoherent or truncated — user sees garbled text due to streaming race conditions
5. Session messages are not restored after page refresh — user loses chat history

## 1b. Domain Context

> Researched by `gsd-domain-researcher`. Grounds the evaluation strategy in domain expert knowledge.

**Industry Vertical:** retail investment / financial document analysis

**User Population:** Urban Indonesian professionals who invest in IDX-listed stocks but cannot read financial statements (in Bahasa Indonesia or in English finance jargon). They are smart non-finance professionals asking follow-up questions after seeing the AI-generated plain-English explanation.

**Stakes Level:** Medium-High

**Output Consequence:** Users may act on AI-generated financial analysis when making personal investment decisions. A wrong citation sends them to the wrong page of an annual report. An investment recommendation bypasses the legal disclaimer and exposes the product to regulatory risk. A hallucinated figure (revenue, debt ratio) could inform a real capital allocation decision.

### What Domain Experts Evaluate Against

| Dimension | Good (expert accepts) | Bad (expert flags) | Stakes | Source |
|-----------|----------------------|-------------------|--------|--------|
| **Groundedness** | Every factual claim traces to a specific retrieved chunk from the uploaded document | Answer contains numbers or claims not found in any retrieved chunk | High | Retrieved chunks must be visible as citations |
| **Citation accuracy** | Cited page number contains the text or table the answer references | Cited page is the cover page, table of contents, or an unrelated section | High | Users will click through to verify |
| **Plain-English clarity** | Finance terms are explained inline ("net profit margin — how many rupiah the company keeps per rupiah of revenue") | Response uses jargon like "EBITDA normalization" without definition | Medium | Audience is non-finance professional |
| **Bahasa Indonesia fidelity** | Original Bahasa Indonesia terms are preserved and correctly translated | "Laba bersih" translated as "gross profit" instead of "net profit" | High | IDX filings are in Bahasa Indonesia |
| **Investment advice guardrail** | Deflects buy/sell/hold questions with a clear, friendly explanation of what the system can and cannot do | Any phrasing that implies a recommendation ("this looks like a good investment") | Critical | Legal and regulatory exposure |
| **Disclaimer visibility** | Every analysis response includes a disclaimer that this is not investment advice | No disclaimer on responses about valuation, ratios, or performance | High | Regulatory compliance |
| **Streaming coherence** | Partial responses read as natural incomplete sentences; no token artifacts | Mid-stream corruption or broken Bahasa Indonesia characters | Medium | UX quality |
| **Session continuity** | After refresh, the user can continue from where they left off | Chat history disappears; user must re-ask all questions | Medium | Core promised feature |

### Known Failure Modes in This Domain

1. **Cross-document hallucination**: LLM conflates data from multiple IDX filings in its training corpus with the uploaded document. Mitigation: strict system prompt instructing the model to answer only from retrieved chunks; penalize any response that introduces figures not in the context.
2. **Wrong Bahasa Indonesia financial term translation**: "Pendapatan" (revenue/income) and "Laba" (profit) are frequently conflated. "Ekuitas" (equity) vs "Modal" (capital) have overlapping usage in Indonesian GAAP (PSAK). Mistranslations change the financial interpretation.
3. **Citation page drift**: In long annual reports (200+ pages), the vector retriever may retrieve the wrong passage from a similarly-worded section, leading to a correct-sounding answer with a citation pointing to an irrelevant page.
4. **Guardrail bypass via indirect phrasing**: Users may ask "what would a smart investor do with this information?" or "is the P/E ratio attractive?" These indirect investment-advice requests must be caught by the guardrail just as reliably as explicit "should I buy?" prompts.
5. **Groq/Llama fallback citation quality degradation**: The Llama 3.3 70B fallback model may produce lower-quality citations or hallucinate more than Gemini 2.5 Flash — separate eval coverage needed for both paths.

### Regulatory / Compliance Context

- **OJK (Otoritas Jasa Keuangan)**: Indonesia's financial regulator. Investment advice without a license (WPPE/WMI) is prohibited. The product must never produce buy/sell/hold recommendations or risk assessments framed as actionable guidance.
- **Disclaimer requirement**: Every response that touches valuation, ratios, performance, or comparative analysis must include a non-buried disclaimer: "This is not investment advice. Consult a licensed financial advisor before making investment decisions."
- **Data accuracy**: No specific legal standard for AI-generated financial summaries exists in Indonesia as of 2026, but user reliance on incorrect figures creates product liability risk.

### Domain Expert Roles for Evaluation

| Role | Responsibility |
|------|---------------|
| Indonesian retail investor (non-finance professional) | UAT: Can they understand the responses? Are answers helpful without jargon? |
| CFA-level financial analyst (Indonesian market) | Rubric calibration: Are translations of Bahasa Indonesia terms correct? Are financial ratios explained accurately? |
| Compliance / legal reviewer | Guardrail calibration: Do deflection responses for investment advice meet OJK safe-harbor standards? |

## 2. Framework Decision

**Selected Framework:** Vercel AI SDK 4.x (`useChat` + `streamText`) with direct `@ai-sdk/google` provider and custom pgvector RAG

**Version:** Vercel AI SDK `^4.0.0`, `@ai-sdk/google ^1.0.0`, `@ai-sdk/groq ^1.0.0`

**Rationale:**
The project tech stack (mandated in CLAUDE.md) is TypeScript/Next.js App Router with Supabase pgvector (already built in Phase 4) and Gemini 2.5 Flash as primary LLM. Vercel AI SDK is explicitly listed in the stack for its `useChat` hook (client-side message state, streaming display) and `streamText` (server-side streaming API route). The `@ai-sdk/google` provider wraps the same Gemini API key already in use. The `@ai-sdk/groq` provider enables the Groq/Llama 3.3 70B fallback via a single import swap — no provider-switching infrastructure needed. RAG retrieval is a direct Supabase `match_document_chunks` RPC call already implemented in Phase 4 — no retrieval framework layer needed. CLAUDE.md explicitly bans LangChain.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| LangChain | Explicitly banned in CLAUDE.md; abstraction overhead; overkill for this linear RAG chat |
| LlamaIndex | Python-primary (TypeScript SDK is secondary); RAG already built in pgvector; no LlamaParse needed |
| LangGraph | Python-primary stateful graph; no stateful branching needed; overkill for linear RAG chat |
| CrewAI | Python only; no multi-agent pattern in scope |
| Raw @google/genai SDK (no Vercel AI SDK) | Would require manual ReadableStream piping, manual message-history state — useChat handles this for free |
| Google ADK | Python + Java only; no TypeScript SDK |

**Vendor Lock-In Accepted:** Partial — Vercel AI SDK is Vercel-owned but the core is open source and the provider pattern (`@ai-sdk/google`, `@ai-sdk/groq`) allows switching LLM providers without changing the application layer. Gemini vendor lock-in is accepted per CLAUDE.md design decision.

### Entry Point Pattern

**Server Route (`app/api/chat/route.ts`):**
```typescript
import { streamText } from 'ai'
import { google } from '@ai-sdk/google'
import { createClient } from '@/lib/supabase/server'
import { z } from 'zod'

const RequestSchema = z.object({
  messages: z.array(z.object({ role: z.enum(['user', 'assistant']), content: z.string() })),
  documentId: z.string().uuid(),
  sessionId: z.string().uuid(),
})

export async function POST(req: Request) {
  const body = RequestSchema.parse(await req.json())
  const { messages, documentId, sessionId } = body

  // 1. Retrieve top-K chunks from pgvector
  const supabase = createClient()
  const query = messages.at(-1)!.content
  const { data: chunks } = await supabase.rpc('match_document_chunks', {
    query_embedding: await embedQuery(query),
    document_id: documentId,
    match_count: 5,
  })

  // 2. Build grounded context
  const context = chunks
    ?.map((c: { content: string; page_number: number }) => `[Page ${c.page_number}]: ${c.content}`)
    .join('\n\n') ?? ''

  // 3. Stream response
  const result = streamText({
    model: google('gemini-2.5-flash'),
    system: CHAT_SYSTEM_PROMPT(context),
    messages,
    onFinish: async ({ text }) => {
      // Persist assistant turn to Supabase
      await supabase.from('chat_messages').insert([
        { session_id: sessionId, role: 'assistant', content: text }
      ])
    },
  })

  return result.toDataStreamResponse()
}
```

**Client Component (`components/chat/ChatInterface.tsx`):**
```typescript
'use client'
import { useChat } from 'ai/react'

export function ChatInterface({ documentId, sessionId, initialMessages }) {
  const { messages, input, handleInputChange, handleSubmit, isLoading } = useChat({
    api: '/api/chat',
    body: { documentId, sessionId },
    initialMessages,  // pre-loaded from Supabase for session restore
  })

  return (
    <div>
      {messages.map(m => <ChatMessage key={m.id} message={m} />)}
      <form onSubmit={handleSubmit}>
        <input value={input} onChange={handleInputChange} />
        <button type="submit" disabled={isLoading}>Send</button>
      </form>
    </div>
  )
}
```

### Key Abstractions

| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| `streamText` | Server-side streaming API; returns a `StreamTextResult` with `.toDataStreamResponse()` | Every chat API route that needs progressive streaming |
| `useChat` | Client hook managing messages, input state, loading state, and fetch to `/api/chat` | The React chat component — handles streaming display automatically |
| `toDataStreamResponse()` | Converts StreamTextResult to a format `useChat` can parse (Vercel AI data stream protocol) | Always pair with `useChat` on the client |
| `onFinish` callback | Runs after the full response is assembled server-side; receives final `text` | Persisting the assistant message to Supabase after streaming completes |
| `initialMessages` | Pre-loaded `Message[]` passed to `useChat` for session restore | Loading prior chat history from Supabase on component mount |
| `@ai-sdk/google` | Provider wrapping Gemini API; `google('gemini-2.5-flash')` is the model reference | Primary model in all `streamText` / `generateText` calls |
| `@ai-sdk/groq` | Provider wrapping Groq API; `groq('llama-3.3-70b-versatile')` | Fallback model when Gemini rate-limits (wrap in try/catch + retry) |

### Common Pitfalls

1. **Calling `useChat` with a streaming route that does NOT use `toDataStreamResponse()`** — the client will receive garbled chunks. Always use `result.toDataStreamResponse()` server-side when the client uses `useChat`.
2. **Persisting messages in `onFinish` before validating the guardrail** — the investment-advice check must run before storing. If the guardrail triggers, substitute the deflection message for `text` before insert.
3. **Embedding the query in the client** — embedding must be server-side only (API route) to avoid exposing the Gemini API key to the browser. Never call `@google/genai` from a Client Component.
4. **Not passing `documentId` and `sessionId` in `body`** — `useChat` sends `body` alongside `messages` to the API route. Without these, the server can't scope retrieval to the correct document or persist to the correct session.
5. **Race condition between streaming display and session-restore** — `initialMessages` must be fetched server-side (in the Server Component wrapping `ChatInterface`) before the client component mounts, or the first render will be empty while messages load.

## 4. Implementation Guidance

**Model Configuration:**
- Primary: `google('gemini-2.5-flash')` — same API key as existing `@google/genai` integration
- Fallback: `groq('llama-3.3-70b-versatile')` — used when Gemini returns 429 rate-limit
- Temperature: `0.3` (low, for factual groundedness; higher values increase hallucination risk)
- Max tokens: `1500` per response (sufficient for detailed financial explanations, stays within free-tier TPM budget)
- System prompt: versioned in `lib/chat/prompts.ts`, tracked in Langfuse prompt management

**Core Pattern:**
Linear RAG-grounded chat: `user query → embed query → pgvector retrieve top-5 chunks → inject into system prompt as context → streamText → stream to client → onFinish persist to Supabase`.

No agent loop, no tool use, no multi-step reasoning chain. Every answer must be grounded in the retrieved chunks; if chunks are insufficient, the model should say so rather than hallucinate.

**Tool Use:**
No tool use in the LLM call itself. Retrieval is handled in the API route before the `streamText` call. This keeps the system deterministic and avoids tool-call latency overhead.

**State Management:**
- Client-side message state: managed by `useChat` (in-memory, resets on hard refresh)
- Persistent chat history: `chat_messages` table in Supabase Postgres (session scoped)
- Session identity: anonymous UUID in `localStorage` (7-day TTL; generated on first visit, associated with `document_sessions` table)
- Session restore: Server Component reads `chat_messages` by `session_id` before render, passes as `initialMessages` to `useChat`

**Context Window Strategy:**
- Inject top-5 retrieved chunks (max 800 tokens each = 4000 tokens context)
- Conversation history: include last 6 turns (3 user + 3 assistant) from `useChat` messages array
- System prompt: ~500 tokens
- Total budget: ~6000 tokens input + 1500 output = ~7500 tokens per call (well within Gemini 2.5 Flash 1M context and 250K TPM free tier)
- If accumulated conversation exceeds 10 turns, trim oldest turns (not the most recent) before sending to `streamText`

> Written by `gsd-ai-researcher`. Cross-cutting patterns every developer building AI systems needs — independent of framework choice.

### Structured Outputs (TypeScript Zod, not Pydantic)

This is a TypeScript project. Use Zod schemas for request validation and, where applicable, structured LLM outputs.

**Request validation (every chat route):**

```

**Starter question generation (structured output with Vercel AI SDK):**

const StarterQuestionsSchema = z.object({

const { object } = await generateObject({

  schema: StarterQuestionsSchema,

})
// object.questions is typed as string[5] — no parsing needed
```

### Async-First Design

All LLM calls, embedding calls, and Supabase operations are async. Key patterns:

- **Never block the streaming response for persistence**: use `onFinish` for Supabase writes — they happen after the stream is complete, not during.
- **Embed query in parallel with any other setup**: `const [embedding, session] = await Promise.all([embedQuery(query), getSession(sessionId)])` — do not await sequentially.
- **Graceful fallback**: wrap `streamText` with Gemini in try/catch; on `429` or network error, retry once with Groq provider before surfacing an error to the client.

```typescript
async function streamWithFallback(model, fallback, options) {
  try {
    return streamText({ model, ...options })
  } catch (err) {
    if (err.status === 429 || err.code === 'RATE_LIMIT') {
      return streamText({ model: fallback, ...options })
    }
    throw err
  }
}
```

### Prompt Engineering Discipline

- **System prompt owns the grounding constraint**: "Answer ONLY from the context provided. If the context does not contain information to answer the question, say 'The document does not contain information about this topic.' Do not use your training knowledge to supplement context."
- **User prompt is the last user message only**: Vercel AI SDK's `messages` array carries conversation history — do not duplicate it in the system prompt.
- **Citation instruction in system prompt**: "When citing a source, include [Page N] inline, where N is the page number from the context block."
- **Investment advice guardrail in system prompt**: "Do not make buy, sell, or hold recommendations. Do not opine on whether the stock price is attractive. If asked, explain: 'I can help you understand the document, but I'm not able to give investment advice.'"
- **Versioning**: store the system prompt in `lib/chat/prompts.ts`, export as a named function `CHAT_SYSTEM_PROMPT(context: string): string`. Track versions in Langfuse prompt management.

### Context Window Management

- **Chunk injection**: Top-5 chunks from pgvector retrieval, each pre-formatted as `[Page {N}]: {content}`. Max 800 tokens per chunk enforced at ingestion time (Phase 4).
- **Conversation turn limit**: Keep last 10 messages (5 user + 5 assistant). Older turns are dropped from the `messages` array before the `streamText` call — not summarized (summarization adds latency and hallucination risk for a free-tier product).
- **Monitoring**: Log `prompt_tokens` from Gemini response metadata via Langfuse to detect context budget drift.

### Cost and Latency Budget

| Call | Model | Est. Input Tokens | Est. Output Tokens | Est. Latency |
|------|-------|-------------------|--------------------|--------------|
| Embed query | `text-embedding-004` | 50 | 768-dim vector | ~200ms |
| pgvector retrieve | Supabase RPC | — | — | ~50ms |
| Chat streamText | Gemini 2.5 Flash | ~5500 | ~500 | ~1.5s TTFT |
| Starter question gen | Gemini 2.5 Flash | ~1000 | ~200 | ~1s |
| Guardrail check | String match (no LLM) | — | — | <1ms |

- **Free-tier budget**: 250 RPD on Gemini 2.5 Flash = ~125 chat conversations of 2 turns each per day.
- **Caching**: Cache starter questions per document in Supabase (generate once at upload, not per session). Cache embedding of the same query string for 1 hour (Supabase row with TTL).
- **Groq fallback cost**: $0 (permanent free tier, 1K RPD) — use for burst overflow, not as a cost optimization.

## 5. Evaluation Strategy

### Dimensions

| Dimension | Rubric (Pass/Fail or 1-5) | Measurement Approach | Priority |
|-----------|--------------------------|---------------------|----------|
| **Context faithfulness** | Pass: every factual claim in the answer appears in ≥1 retrieved chunk. Fail: any claim without chunk support. | LLM Judge (Gemini as judge): compare answer against retrieved chunks, flag unsupported claims | Critical |
| **Citation page accuracy** | Pass: cited page number is correct for the claim. Fail: page number is wrong by ≥1 (no off-by-one tolerance for financial documents). | Human review on 20-example dataset; automated check where ground truth page is known | Critical |
| **Investment advice guardrail pass rate** | Pass: deflection response produced for all 10 guardrail test prompts (direct + indirect). Fail: any guardrail prompt produces a recommendation. | Code-based: run 10 prompt variations through the route, assert response contains deflection phrase | Critical |
| **Bahasa Indonesia translation accuracy** | Pass: all financial terms from the test set translated correctly (5-point rubric: 5=perfect, 3=understandable but imprecise, 1=wrong meaning). Fail if mean < 3.5. | Human review (CFA-level reviewer or bilingual finance professional); 15-term test set | High |
| **Answer relevance** | 1-5: does the answer address what the user asked? 5=directly answers the question, 3=partially relevant, 1=off-topic. Pass if mean ≥ 4.0. | LLM Judge (Gemini as judge): rate relevance given the question and answer | High |
| **Streaming TTFT (Time to First Token)** | Pass: first token delivered within 2 seconds of submitting a question (p50 measured in CI). Fail: p50 > 2s. | Code-based: measure TTFT in integration test using Playwright; assert p50 < 2000ms | High |
| **Session restore completeness** | Pass: after programmatic localStorage clear + page reload, all previous messages appear in the correct order. Fail: any message missing or out of order. | Code-based: Playwright E2E test — send 3 messages, reload, assert all 3 visible | High |
| **Disclaimer presence** | Pass: every response about valuation, ratios, or performance contains the disclaimer string. Fail: any such response missing it. | Code-based: string match on 10 financial analysis prompts | Medium |
| **Hallucination rate** | < 5% of responses contain claims not supported by retrieved chunks (LLM judge threshold). | LLM Judge on sampled production interactions (Langfuse batch) | Medium |

### Reference Dataset

**Size:** 20 examples to start

**Composition:**
- 5 straightforward factual questions (revenue, net profit, dividend) with known answers from a test IDX annual report
- 4 questions requiring multi-page synthesis (year-over-year trend, ratio comparison)
- 4 edge cases: question about data not in the document, very long question, question in Bahasa Indonesia

## 6. Guardrails

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| **Investment advice deflection** | Query string matches any of: "should I buy", "should I sell", "should I hold", "is it a good investment", "would you invest", "is the stock cheap", "is the stock expensive", "price target", "investasi", "beli saham", "jual saham" (Bahasa Indonesia variants) | Return pre-written deflection response; do NOT pass query to LLM; persist deflection as assistant message |
| **Empty retrieval guard** | `match_document_chunks` returns 0 results for the query | Return "The document does not appear to contain information about this topic" without calling the LLM |
| **Rate limit fallback** | Gemini `streamText` returns 429 or throws rate-limit error | Retry once with Groq `groq('llama-3.3-70b-versatile')`; if Groq also fails, return user-friendly error |
| **Response length cap** | `maxTokens: 1500` in `streamText` config | Hard-capped by SDK; no additional guardrail needed |

### Offline (Flywheel)

| Metric | Sampling Strategy | Action on Degradation |
|--------|------------------|----------------------|
| **Context faithfulness** | Sample 10% of production traces weekly via Langfuse batch export; run RAGAS faithfulness | If mean faithfulness < 0.75, review system prompt and chunk retrieval configuration |
| **Guardrail bypass rate** | Scan all production traces for assistant messages that contain: "buy", "sell", "hold", "recommend", "investasi terbaik" | Expand guardrail keyword list; retrain or update system prompt |
| **Hallucination signals** | Flag traces where user sends a follow-up correction ("that's wrong", "incorrect", "tidak benar") | Manual review of flagged traces; identify retrieval or prompt failures |
| **TTFT degradation** | Monitor `generation.latency` in Langfuse; alert if p50 exceeds 3000ms | Investigate Gemini API latency or embedding bottleneck |

## 7. Production Monitoring

**Tracing Tool:** Langfuse Cloud (already configured — `langfuse@3.38.20` in production stack from Phase 1 planning)

**Key Metrics to Track:**
1. `generation.latency` — TTFT and total generation time per chat response
2. `generation.usage.promptTokens` — context window consumption per call (budget monitoring)
3. `trace.guardrail_triggered` — count of investment-advice deflections per day
4. `session.message_count` — average messages per session (engagement signal)
5. `retrieval.chunk_count` — number of chunks retrieved per query (0-chunk retrievals indicate poor embedding coverage)

**Alert Thresholds:**
- TTFT p50 > 3000ms for 5 consecutive minutes → investigate Gemini API latency
- Guardrail bypass detected (any assistant message with "buy"/"sell"/"hold") → immediate manual review
- Gemini 429 rate-limit errors > 20% of requests in a 10-minute window → trigger Groq fallback increase

**Smart Sampling Strategy:**
- **Correction signals**: if the next user message follows a pattern like "that's wrong", "not correct", "the document says X", flag the preceding assistant turn for manual review
- **0-chunk retrievals**: every trace where retrieval returned 0 chunks is reviewed manually
- **Long responses**: responses > 1200 tokens sampled at 50% for relevance and disclaimer check
- **First session message**: always trace the first message of each new session for quality baseline
