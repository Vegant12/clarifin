## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`) |
| sm | 8px | Compact element spacing (`gap-2`), message bubble padding |
| md | 16px | Default element spacing (`gap-4`), chat input horizontal padding |
| lg | 24px | Section padding (`gap-6`), chat panel vertical padding |
| xl | 32px | Layout gaps (`gap-8`) |
| 2xl | 48px | Major section breaks (`gap-12`, matching ExplanationPanel) |
| 3xl | 64px | Page-level spacing — not used in chat panel |

Exceptions:
- Chat input minimum touch target: 44px height (`min-h-[44px]`) to meet WCAG 2.5.5 for mobile — this is a 4px overshoot from the xl token. Use explicitly on the send button and textarea.
- Starter question pill height: 36px (`h-9`) — standard shadcn Button sm variant, within 8-point grid.

Component-level Tailwind overrides (not spacing scale tokens):
- Citation badge inner padding: `px-1.5 py-0.5` — this is an **inherited Phase 7 CitationInline convention** applied at the component level. It is not a named spacing scale slot and should not be treated as one during execution. Apply it verbatim from `CitationInline`'s existing class list.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (text-base) | 400 (normal) | 1.625 (leading-relaxed) |
| Label / metadata | 14px (text-sm) | 400 (normal) | 1.5 (leading-normal) |
| Heading | 20px (text-xl) | 600 (semibold) | 1.25 (leading-tight) |
| Label / metadata (semibold) | 14px (text-sm) | 600 (semibold) | 1.25 |

Notes:
- Message body text: 16px / 400 / leading-relaxed — matches `ExplanationPanel` prose style exactly.
- Timestamps, metadata, and session info (deflection disclaimer, starter pill labels): 14px / 400 — "Label / metadata" row.
- Guardrail deflection heading: 14px / 600 — "Label / metadata (semibold)" row.
- Section label "Chat" or panel heading: 20px / 600 — matches existing section headings in ExplanationPanel (`text-xl font-semibold`).
- Citation badges in chat messages: `text-xs` (12px) applied as a **Tailwind component-level utility** on `ChatCitationBadge`, not a named type scale slot. This inherits the Phase 7 `CitationInline` class list (`px-1.5 py-0.5 text-xs`) verbatim. Do not promote to a scale slot.
- Starter question pills: 14px (text-sm) / 400 — shadcn Button sm default.

Source: Codebase analysis — `explanation-panel.tsx` uses `text-base leading-relaxed`, `text-xl font-semibold`, `text-sm text-muted-foreground`. This phase reuses those exact classes for visual consistency.

## Layout Contract

### Desktop (≥769px) — Split Pane Extension

The `DocumentReaderLayout` left panel currently shows `ExplanationPanel`. Phase 10 adds `ChatPanel` below the explanation content within the same scrollable left panel.

```
Left Panel (scrollable, overflow-auto)
├── ScoreCard
├── StockWidget (if ticker detected)
├── TrendChartCard (if chart data)
├── ExplanationPanel sections (Revenue, Profitability, Balance Sheet, Cash Flow, Key Risks)
└── ChatPanel  ← NEW (Phase 10)
    ├── <h2> Chat (text-xl font-semibold)
    ├── StarterQuestions (shown only when messages.length === 0)
    │   └── [FOCAL POINT — empty-session state]
    │       Primary visual anchor: "Start with a question" heading + starter question pills.
    │       The textarea is secondary — visible but not the first eye-stop.
    ├── Message list (scrollable, max-h not set — natural document scroll)
    │   ├── ChatMessage (user)
    │   ├── ChatMessage (assistant, with CitationBadges)
    │   └── ChatLoadingSkeleton (shown when isLoading)
    └── Chat input form
        ├── <textarea> (auto-grow, 1–4 rows)
        └── Send Message button
```

The chat panel is appended to the existing left-panel scroll context — no nested scroll within the chat list. This avoids scroll-within-scroll UX problems on desktop.

### Mobile (≤768px) — New Tab

Add a "Chat" tab to `MobileTabView` alongside "Explanation" and "Source PDF".

```
TabsList (full-width, border-b)
├── TabsTrigger: "Explanation"
├── TabsTrigger: "Source PDF"
└── TabsTrigger: "Chat"  ← NEW

TabsContent value="chat"
└── <div className="flex h-full flex-col overflow-hidden">
    ├── Message list (flex-1, overflow-auto)
    │   ├── ChatMessage (user)
    │   ├── ChatMessage (assistant)
    │   └── ChatLoadingSkeleton
    └── Chat input form (sticky bottom, border-t)
        ├── <textarea>
        └── Send Message button
```

On mobile, the chat input is sticky at the bottom of the tab content. The message list is `flex-1 overflow-auto` — this is the only tab where we use an inner scroll container, because the tab forces a fixed height context.

## Chat Message Visual Contract

### User Message

```
<div className="flex justify-end">
  <div className="max-w-[85%] rounded-2xl rounded-br-sm bg-muted px-4 py-3">
    <p className="text-base text-foreground leading-relaxed">{message.content}</p>
  </div>
</div>
```

- Aligned right.
- Background: `bg-muted` (zinc-100) — secondary surface color.
- Border-radius: `rounded-2xl rounded-br-sm` — speech bubble pointing right.
- Max width: 85% of container — prevents full-width messages that look like banners.
- No avatar or icon — session is anonymous; persona is implicit.

### Assistant Message

```
<div className="flex justify-start gap-3">
  <div className="max-w-[90%] flex flex-col gap-2">
    <div className="rounded-2xl rounded-bl-sm bg-background border border-border px-4 py-3">
      <p className="text-base text-foreground leading-relaxed">
        {/* rendered segments: text + CitationBadge inline */}
      </p>
    </div>
    <p className="text-xs text-muted-foreground px-1">
      This is not investment advice.
    </p>
  </div>
</div>
```

- Aligned left.
- Background: `bg-background` (white) with `border border-border` — matches card style.
- Border-radius: `rounded-2xl rounded-bl-sm` — speech bubble pointing left.
- Max width: 90% — assistant messages can be longer.
- Disclaimer line: every assistant message that discusses financials appends "This is not investment advice." as `text-xs text-muted-foreground`. This satisfies DISCLAIM-01.

### Guardrail Deflection Message

```
<div className="flex justify-start">
  <div className="max-w-[90%] rounded-lg border border-border bg-muted/30 px-4 py-3 flex flex-col gap-2">
    <p className="text-sm font-semibold text-foreground">I can't help with that</p>
    <p className="text-sm text-foreground leading-relaxed">
      I can help you understand what's in the document, but I'm not able to give 
      buy/sell recommendations or investment advice.
    </p>
  </div>
</div>
```

- Styled as a neutral info box — `bg-muted/30 border-border` — not red/destructive.
- Heading in `font-semibold` to distinguish from regular assistant prose.
- Tone: friendly, not scolding.

### Citation Badge in Chat (ChatCitationBadge)

Visually identical to Phase 7 `CitationInline`:
```
className="inline-flex cursor-pointer items-center rounded-full bg-primary px-1.5 py-0.5
           text-primary-foreground text-xs
           focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-1
           hover:shadow-sm"
```

The `px-1.5 py-0.5` padding and `text-xs` size are inherited verbatim from Phase 7 `CitationInline` — they are component-level Tailwind overrides, not spacing scale tokens.

Label: `[p.{N}]` — same format as Phase 7. Clicking fires `onGoToPage(page)` to jump the PDF viewer to that page.

## Loading and State Contracts

### Streaming Loading Indicator

While `isLoading === true` (after user submits, before first token):

```
<div className="flex justify-start gap-3">
  <div className="rounded-2xl rounded-bl-sm bg-background border border-border px-4 py-3">
    <div className="flex gap-1 items-center" role="status" aria-label="Clarifin is thinking">
      <span className="h-2 w-2 rounded-full bg-muted-foreground animate-bounce [animation-delay:-0.3s]" />
      <span className="h-2 w-2 rounded-full bg-muted-foreground animate-bounce [animation-delay:-0.15s]" />
      <span className="h-2 w-2 rounded-full bg-muted-foreground animate-bounce" />
    </div>
  </div>
</div>
```

Three-dot bounce animation using Tailwind `animate-bounce` with staggered `animation-delay`. Shown at left-aligned position matching assistant messages. Disappears when first token arrives (streaming replaces it).

### Chat Input Disabled State

While `isLoading === true`:
- Textarea: `disabled` attribute, `opacity-60 cursor-not-allowed`.
- Send button: `disabled` attribute, default disabled styling from shadcn Button.
- Do NOT show a spinner inside the send button — the three-dot animation in the message list is sufficient feedback.

### Starter Questions Loading State

Starter questions are pre-generated server-side (cached in `document_analysis`). If not yet available (null), render nothing — do not show a skeleton for starter questions. The chat input is always available regardless.

### Session Restore State

If `initialMessages.length > 0` on mount (session history loaded from Supabase), render the message list directly with no transition. No "loading history" indicator — the RSC pre-loads messages before hydration, so there is no visible flash.

### Error State

If the chat API route returns a non-streaming error:
- `useChat` surfaces this via its `error` property.
- Show an inline error below the input:
  ```
  <p className="text-sm text-destructive px-1">
    Connection error — please try again.
  </p>
  ```
- The input and send button remain enabled (user can retry immediately).

## Interaction Contracts

### Textarea Auto-Grow

- Initial height: 1 row (`min-h-[44px]`).
- Maximum height before scrolling: 4 rows (`max-h-[112px]`, calculated as 4 × 28px line height).
- Implementation: CSS `resize: none; overflow-y: auto` + `rows={1}` attribute. Use a `useEffect` that sets `element.style.height = 'auto'` then `element.style.height = element.scrollHeight + 'px'` on every `input` event, capped at 112px.
- On submit: textarea resets to 1-row height.

### Send on Enter

- `Enter` alone submits the form (calls `handleSubmit`).
- `Shift+Enter` inserts a newline without submitting.
- Textarea `onKeyDown` handler: `if (e.key === 'Enter' && !e.shiftKey) { e.preventDefault(); handleSubmit(e) }`.
- Send button always present as the primary action — accessible for mobile and keyboard users who prefer clicking.

### Starter Question Click

- Clicking a starter question pill populates the `input` field via `useChat`'s `setInput` (or append pattern) and immediately submits.
- Do not just populate the field and wait — auto-submit provides faster feedback for the target audience.
- Pills disappear once `messages.length > 0` — they are only shown for the empty session state.

### Citation Click in Chat

- Clicking a `ChatCitationBadge` calls the `onGoToPage(pageNumber)` callback prop.
- On desktop: this scrolls the right-panel PDF viewer to that page (same behavior as Phase 7 `CitationInline`).
- On mobile: clicking a citation in the Chat tab should switch the active tab to "Source PDF" and scroll to the page. Implementation: lift `onGoToPage` to `MobileTabView` level; it calls `setActiveTab('pdf')` then `pdfRef.current?.scrollToPage(page)`.

### Scroll to Latest Message

- On new message arrival (streaming start or session restore), scroll the message list to the bottom.
- Use a `useEffect` that watches `messages` array length and calls `ref.current?.scrollIntoView({ behavior: 'smooth' })` on a sentinel element at the bottom of the list.
- Do NOT auto-scroll while the user is manually scrolled up (implement scroll-lock: track `isAtBottom` state; only auto-scroll if `isAtBottom`).

| Element | Copy |
|---------|------|
| Primary CTA (send button) | "Send Message" |
| Chat section heading | "Chat" |
| Textarea placeholder | "Ask anything about this document…" |
| Empty state heading | "Start with a question" |
| Empty state body | "Ask about revenue, debt levels, risks, or anything in the document. Clarifin finds the answer from the source pages." |
| Starter questions label | None — pills are shown without a label above them |
| Guardrail deflection heading | "I can't help with that" |
| Guardrail deflection body | "I can help you understand what's in the document, but I'm not able to give buy/sell recommendations or investment advice." |
| Empty retrieval error | "The document doesn't seem to contain information about that topic. Try asking about the company's financials, risks, or performance." |

| Session restore (no heading needed) | Messages render inline — no "session restored" toast |

Notes:
- "Ask anything about this document…" uses "anything" deliberately — non-finance users may feel their questions are "too basic." The phrasing is welcoming.
- "Send Message" (verb + noun) is more explicit than "Send" alone and consistent with the downstream consumer pattern for CTA labels.
- The guardrail message does not apologize excessively — one clear explanation, then the user can ask something else.
- "Clarifin" brand name is used in empty state to reinforce product voice.
- "Connection error — please try again." gives a brief cause hint (connection, not an unspecified failure) without technical jargon.

## Accessibility Contract

- Textarea: `aria-label="Ask about this document"` + `aria-required="true"`.
- Send button: `type="submit"`, disabled when `isLoading`. No icon-only button — text label "Send Message" is always visible.
- Loading indicator: `role="status" aria-label="Clarifin is thinking"` on the three-dot animation container.
- Message list: `role="log" aria-live="polite" aria-label="Chat messages"` on the scrollable container. Each `ChatMessage` is a `<article>` or `<div role="article">`.
- Citation badges: inherit Phase 7 `CitationInline` accessibility — `role="button" tabIndex={0} aria-label="View source for page N"`.
- Starter questions: `role="list"` on the pill container; each pill is a `<button>` with explicit `aria-label="Ask: {question text}"`.
- Guardrail box: no `role="alert"` — the message is part of the normal chat flow, not an urgent interruption. Standard `role="article"` is correct.
- Mobile tab "Chat": inherits `TabsTrigger` ARIA from shadcn Tabs — no additional work needed.

## Mobile-Specific Contracts (375px minimum)

- Input form: `position: sticky; bottom: 0; background: white; border-top: 1px solid border` — prevents virtual keyboard overlap on mobile.
- Message list: `padding-bottom: 8px` inside the scroll container so the last message is not clipped by the sticky input.
- Starter question pills: `flex-wrap: wrap` so they wrap on narrow viewports — do not use horizontal scroll.
- Chat tab in `MobileTabView`: add after "Source PDF" tab, maintaining existing `data-[state=active]:border-primary data-[state=active]:border-b-2` active style.
- Touch targets: send button and starter pills minimum 44px tall.
