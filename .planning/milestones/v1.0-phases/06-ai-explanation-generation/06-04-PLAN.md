## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → /api/internal/analyze-batch | External callers must authenticate via INTERNAL_PARSE_SECRET |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-6-02 | Spoofing | Unauthorized invocation of `/api/internal/analyze-batch` triggers Gemini quota burn or stalls a doc | mitigate | Route copies `timingSafeStringEq(candidate, env.INTERNAL_PARSE_SECRET)` verbatim from embed-batch route (Pattern Map). Returns 401 on any mismatch — verified by Task 3 test case (a) and (b). |
| T-6-03 | Information disclosure | `INTERNAL_PARSE_SECRET` leaks via error logs | mitigate | Secret is read only via `env.INTERNAL_PARSE_SECRET` (server-only env module). Never logged. timingSafeEqual prevents timing side-channel even on length mismatches. |
| T-6-04 | DoS / Cost | An attacker that obtains the secret could fire many requests | accept (Phase 6) | Cron fires once per minute; `runAnalyzeBatch` itself has a `LIMIT 1` doc picker and a cache short-circuit. Per-IP rate limiting and concurrency cap are Phase 11/12 work (INFRA-02, INFRA-03). |
| T-6-10 | Tampering | `scheduleAnalyzeBatchForDoc` fires for a docId the caller does not own | accept | The trigger is called by trusted server-side code (`embed-document-batch.ts`) using a docId already validated by the embed flow. No user-controlled docId enters the trigger path. |
</threat_model>
